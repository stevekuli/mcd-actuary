# 凑单组合生成策略

目标：在 ≤8 次 `calculate-price` 内找到预算内的最省组合。

## 候选生成顺序

### 第 1 梯队：必吃项套餐化（最多 3 个候选）
用户必吃项往往有套餐形态（如"堡+薯条+可乐"→ 对应套餐通常比单点便宜 5-15 元）。
1. 用 `query-meal-detail` 查必吃单品的套餐组成
2. 生成：纯套餐版 / 套餐+换购版 / 单点版 各一，互相对比

### 第 2 梯队：券门槛凑单（最多 3 个候选）
从可用券池按「面额/门槛比」排序取 Top 券，反向凑单：
1. 取出门槛略高于当前组合小计的券（如组合 ¥28，有"满30减10"）
2. 从菜单中选「价格 ≥ 缺口且最接近缺口」的单品补齐（甜筒、小薯是经典凑单品）
3. 凑单原则：**为凑券多花 1 元，至少省回 2 元**，否则放弃该券

### 第 3 梯队：活动联动（最多 2 个候选）
对照 `campaign-calendar` 今日活动：
- 会员日特价品优先入组合
- "第二件半价""加价购"类活动，计算边际成本后决定是否加入

## 试算纪律

- 候选总数 ≤8；超出时按「必吃匹配度 > 预估实付低 > 券利用率高」裁剪
- 每个候选 `calculate-price` 时把「计划用的券」一并传入，拿到真实券后价
- 若某候选返回券不适用，记录原因并从报告中降级，不反复重试

## 排序与输出

排序键（优先级从高到低）：
1. **实付金额**升序（硬指标）
2. 必吃项覆盖率
3. 总热量合理性（用户提健身时启用，查 `list-nutrition-foods`）

输出 Top 3 + 一句「精算师点评」，点评要点：
- 最优方案为什么最优（券用满了 / 套餐价差 / 活动叠加）
- 是否存在"多花 X 元多得 Y"的升级机会（给用户选择权，不替他决定）

## 超预算处理

所有组合 > 预算时输出两条路：
- **最接近方案**：实付最低组合，标注超出金额
- **砍单方案**：移除哪个单品/降级哪个规格可回到预算内（优先砍"凑单品"，保必吃项）
